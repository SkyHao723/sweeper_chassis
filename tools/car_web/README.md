# 小车遥控器 Web（RK3576 → STM32 → 达妙 DM-H65）

浏览器里的虚拟摇杆遥控器。它**不再直连 USB-CAN**，而是由 RK3576 上的这一个进程
独占 `/dev/wheeltec_controller`，按 STM32 桥的串口协议收发：

```
浏览器（手机/电脑）
   │  WebSocket：20 Hz 指令 + 20 Hz 状态
   ▼
car_web.py（本进程，唯一碰串口的一线程）
   │  115200 8N1：11 字节命令帧 / 收 24+44 字节帧
   ▼
STM32 桥（firmware/stm32-chassis）── CAN 1 Mbps ──> 左/右 DM-H65 轮毂电机（ID 1/2）
```

Web 端只用标准库 `http.server` + 自己实现的极简 WebSocket，**不依赖 FastAPI/uvicorn**。

## 2. 依赖与启动

- Python 3.10+（Windows 上用 3.12.8 自测；RK3576 上是 3.10）
- `pyserial`（真机必需；RK3576 已装）
- 不需要 NumPy / FastAPI / uvicorn / node

```bash
cd tools/car_web

python3 car_web.py --sim          # 仿真：不占串口，UI/API/安全逻辑全跑
python3 car_web.py                # 真机：/dev/wheeltec_controller @115200
python3 car_web.py --port 8001    # 8000 被占用时换端口
```

浏览器打开 `http://<RK3576_IP>:8000`（本机 `http://127.0.0.1:8000`）。
启动时终端会打印三个地址，其中局域网地址就是给手机用的那个。

| 参数 | 默认 | 说明 |
|---|---|---|
| `--host` | `0.0.0.0` | 监听地址 |
| `--port` | `8000` | 监听端口（`tools/chassis_web.py` 占的是 8080，避开） |
| `--serial` | `/dev/wheeltec_controller` | 串口设备；udev 已建好该符号链接 |
| `--baud` | `115200` | 8N1 |
| `--sim` | 关 | 内部仿真，产生与固件逐字节同格式的帧 |
| `--tx-hz` | `30` | 命令帧频率，只允许 20~50（固件看门狗 800 ms） |
| `--verbose` | 关 | 每秒一行统计 + HTTP 访问日志 |

建议在 RK3576 上先跑 `python3 car_web.py --sim` 确认页面和手机都能打开，再换成真机。

### 可选：systemd 开机自启


## 3. 界面怎么用

- **摇杆**：圆形区域，上下 = `vx`（前/后），左右 = `wz`（右推右转）。
  鼠标按住拖动、触摸拖动都行（Pointer Events）。中心有 10% 死区防手抖。
- **档位**：驾驶卡里的 6 档（低速/中速/高速/快速/极速/超快），同时限制
  `vx` 和 `wz`（见下表），当前上限显示在驾驶卡的胶囊里；键盘 `1~6` 也能切。
  **默认低速 0.15 m/s**。手机上档位按钮自动排成 3×2，不会挤成一条。
  `≥0.8 m/s` 的速度数字变橙、`≥1.2 m/s` 变红；快速/极速/超快三档在
  档位区还会显示“请在空旷场地测试”的橙色/红色提示。
- **急停**：右上角大红按钮。按下立即发 0 并**锁存**，之后无论怎么推摇杆都只发 0；
  必须点“复位”才能再动，且复位后要重新推摇杆（不会自己恢复上一目标）。
- **键盘**：`W A S D` / 方向键，空格 = 立即停。桌面调试很方便。
- **缓启缓停**：驾驶卡里的滑动开关，**默认开**。加速和减速用**不同斜率**：
  `vx` 加速 `1.0 m/s²`、减速 `0.40 m/s²`；`wz` 加速 `4.0 rad/s²`、减速
  `1.50 rad/s²`。松手 / 摇杆回中 / 键盘松开 / 点“回中 / 停止”会走减速斜率
  **软停**，状态行显示“缓停中”（不再是笼统的“斜坡中”）；关闭开关后恢复
  旧的阶跃行为（加速和停车都立即到位）。
  **切页、窗口失焦、页面关闭、急停、心跳超时仍然立即发 0，不走软停**（见 §4）。
- **电机详情**（左右轮各一张，44 字节状态帧 20 Hz）：
  - 大数字 = 实际 ω（rad/s），黄色竖线 = 目标 ω；条形图满量程 ±6 rad/s。
  - **偏差 = |实际 ω − 目标 ω|**：`≤0.5` 绿、`≤2` 橙、`>2` 红；`|目标|≥0.5 rad/s`
    时再显示**跟随度**百分比（目标太小时显示 `—`，避免除零误差）。
    API 里的 `dev` 仍保留符号（目标−实际），界面只显示幅值以免和“前进为负”混淆。
  - **扭矩 τ（Nm）** + 趋势条（±10 Nm，`|τ|≥8` 变橙）。这是达妙**反馈的扭矩**，
    不是相电流（见 §3.1 后面的说明）。
  - **累计位置**（rad，电机上电以来的累计角度，来自 `[24..27]`）。
  - **ERR**：中文翻译；`0=失能 / 1=使能` 算正常，其它码（过流/过温/通讯丢等）红色高亮。
  - **MOS / 线圈温度**：`>70℃` 橙、`>85℃` 红；任一超限整张轮卡描边。
  - **反馈年龄**（ms）：`>200 ms` 橙、`>500 ms` 红/虚线描边；`从未收到` 直接红。
    这是判断“电机掉线”最直接的指标（固件 `[32..35]`）。
- **flags**：8 个中文字段，绿=正常、红=异常（在线/使能/命令超时/故障/IMU）。
- **IMU / 姿态**：六轴数值（m/s²、rad/s）+ **加速度模长 |a|**（静止应≈9.81，
  偏离说明振动/碰撞/姿态变化或某轴被 ±2g 量程夹住）+ 水平泡 + gz/ax 波形 +
  **IMU 体检**（版本/陀螺/磁力/陀螺是否读到过，来自 `[39]` 与 `[31][38][40]`）。
- **里程**：用**实际** `vx/wz` 积分（不是命令值），可清零；偏航角折到 ±180°。
- **链路诊断**：串口、遥测/状态帧年龄、发送/帧计数、坏帧/重同步、
  底盘回读指令、**启动阶段**（中文，`[41]`）、IMU 诊断、**CAN 失败 / 反馈帧总数**
  （`[28][29]`）、左右**反馈年龄**摘要。异常项按绿/橙/红分级。

> **关于“电流”**：达妙 DM-H65 反馈帧里的 T 是 **12 bit 扭矩**（`TMAX=40 Nm`），
> 不是相电流 A。本固件只写控制模式，**没有读 KT 寄存器（0x01 `KT_Value`）**，
> 因此本页**不显示电流、也不做 Nm→A 换算**；需要电流请在固件里先读 KT 系数
> 再自行换算，网页不会编一个假值。

| 档位 | key | vx 上限 | wz 上限 | 提示 |
|---|---|---|---|---|
| 低速 | `low` | 0.15 m/s | 0.50 rad/s | 默认；室内/桌边测试 |
| 中速 | `mid` | 0.30 m/s | 0.75 rad/s | 常规 |
| 高速 | `high` | 0.50 m/s | 1.00 rad/s | 常规上限 |
| 快速 | `fast` | 0.80 m/s | 1.15 rad/s | **橙色警告** |
| 极速 | `sprint` | 1.20 m/s | 1.30 rad/s | **红色警告** |
| 超快 | `ultra` | 1.60 m/s | 1.50 rad/s | **红色警告** |

硬上限永远存在：`|vx| ≤ 2.0 m/s`、`|wz| ≤ 1.5 rad/s`（服务端再夹一次，不信前端）。
**绝不能超过固件能力**：单轮 `MAX_OMEGA_RAD_S = 30 rad/s × WHEEL_R_M 0.0855 m =
2.565 m/s`。取 2.0 m/s 留 0.565 m/s 余量；按**新轮距 0.456 m** 算最坏组合
`|vx| + |wz|·TRACK/2 = 2.0 + 1.5×0.228 = 2.342 m/s → 27.4 rad/s < 30`，
不会被固件削顶。改大 `HARD_*` 或再换轮距前先把这条算式重算一遍。

> ⚠ **高速档请在空旷场地测试。** 软停的减速度是固定的 0.40 m/s²，
> 速度越高、滑行距离越长：1.20 m/s 软停约 3.0 s / 1.8 m，1.60 m/s 约
> 4.0 s / 3.2 m。场地不够时请用低速档，或直接按急停（急停立即归零）。

### 3.1 方向约定（改符号前先看这里）

固件逆解是：

```text
v_left  = vx - wz * TRACK/2
v_right = vx + wz * TRACK/2
```

所以 **`wz > 0` = 左轮慢/右轮快 = 车向左转（逆时针）**；
“右推摇杆 = 右转”就必须发 **`wz < 0`**。

- 前端 `static/app.js` 顶部有唯一取反点：

  ```js
  const WZ_CMD_SIGN = -1;
  // steerWz(右推量, 档位上限) = WZ_CMD_SIGN * 右推量 * 上限
  ```

  摇杆和键盘 `D/→` 都调用 `steerWz()`，不要再在别处写裸负号。
  以后要反方向，只改 `WZ_CMD_SIGN` 这一处。
- **后端 `car_web.py` 不再二次取反**：它收到的是协议值，`build_cmd_frame()`
  原样编码成 11 字节帧。否则会双重取反，右推变左转。
- **遥测/轮速显示保持实际值**：24 字节帧的 `wz`、44 字节帧的左右轮 `ω`
  都是固件按实际反馈算出来的，**不在显示层翻转**；界面上的符号就是车体真实方向。
- `vx` 的前进方向由固件 `DM_DIR_SIGN = -1` 负责（前进为正），网页端不动它。

## 4. 安全设计（三层，任一层失效都还能停）

| 层 | 触发 | 行为 |
|---|---|---|
| 浏览器 | 松手 / 摇杆回中 / 键盘松开 / 点“回中 / 停止” | 发普通 `vx=0,wz=0`（**后端软停**） |
| 浏览器 | 切后台（visibilitychange）/ 窗口失焦 / 页面关闭（pagehide） | 发 `vx=0,wz=0,hard=true`（**后端立即停**），关页时再关 WebSocket |
| 服务端 | 500 ms 没收到网页指令（WebSocket 断开也会立刻清） | 立即发 0；`cmd.reason = timeout` |
| 服务端 | 急停 | 锁存，立即只发 0，直到 `/api/estop/reset` |
| 服务端 | 任何指令 | 先按档位、再按 ±2.0 / ±1.5 硬夹；NaN/Infinity 直接归零 |
| 服务端 | 缓启缓停开启时的**正常行驶**指令 | 按加速斜率 `vx 1.0 m/s²` / `wz 4.0 rad/s²` 逼近目标（默认开） |
| 服务端 | 缓启缓停开启时的**主动停车** | 按减速斜率 `vx 0.40 m/s²` / `wz 1.50 rad/s²` **软停**（默认开） |
| 服务端 | 缓启缓停开启时的**安全停车** | 急停 / 超时 / 断连 / `hard:true` **下一拍直接归零**，不受斜坡影响 |
| STM32 | 800 ms 没收到合法命令帧（固件） | 目标清零（不使能、不失能，保持零速） |

其他实现细节：

- 串口由**一个线程**（`LinkWorker`）顺序做 `read → 组帧 → write`，不存在两个线程抢同一个 fd；
  POSIX 上用 `exclusive=True`（TIOCEXCL）打开，尽量阻止别的进程同时读。
- 串口打不开**不退出进程**：HTTP/WS 照常提供，每秒重试一次，`/api/state` 里能看到原因，
  这样现场可以先开网页排查接线。
- WebSocket 断开时只有“最后发指令的那个客户端”会把目标清零；
  开第二个标签页只看状态，不会把正在开的车弄停。
- **急停锁存期间收到的指令只计数、不生效**（目标保持 0、时间戳清零），
  复位后不会把锁存期间最后一帧指令“放出来”，必须重新推摇杆。
- 浏览器 20 Hz 持续发（包括 0），既是控制也是心跳；后台标签页被浏览器节流后
  自然超过 500 ms，服务端会归零 —— 这是期望行为。

### 4.1 缓启缓停为什么放在后端

斜坡在 `CarHub.step_output()` 里推进，只有 `LinkWorker` 这个串口线程按 20~50 Hz
调用它；`snapshot()` / HTTP 线程只读，不积分。这样做的好处：

1. 前端断网/卡顿/标签页被节流时，后端仍按自己的节拍平滑过渡，不会因为
   网页 20 Hz 抖动而一冲一冲；
2. 与 500 ms 心跳、800 ms 固件看门狗在同一层，不会出现“网页还在斜坡、
   服务端已经超时归零”的互相打架；
3. 前端只负责开关状态，控制律只有一份。

### 4.2 停车场景分类（哪些软停、哪些立即停）

**"松手/回中"是正常停车，走软停；"可能看不到车了"是安全停车，立即归零。**
这是两条不同的代码路径：安全停车由 `estop` / `timeout` / `self.hard_stop`
在 `step_output()` 里直接置 0；主动停车只是把目标置 0，交给减速斜坡。

| 场景 | 触发路径 | 行为 | 原因 |
|---|---|---|---|
| 松手 | 摇杆 `pointerup/pointercancel/lostpointercapture` | **软停** DEC | 用户还在看着车 |
| 摇杆回中 | 摇杆进入中心 10% 死区 | **软停** DEC | 同上 |
| 键盘松开 | `keyup`（WASD/方向键） | **软停** DEC | 同上 |
| 空格 / “回中 / 停止”按钮 | 前端发普通 0 | **软停** DEC | 主动正常停车 |
| `POST /api/stop`（不带 hard） | 脚本/HTTP 客户端 | **软停** DEC | 主动正常停车 |
| 切后台 / 页面隐藏 | `visibilitychange` + `hard:true` | **立即 0** | 用户可能已经看不到车 |
| 窗口失焦 | `blur` + `hard:true` | **立即 0** | 同上 |
| 页面关闭 | `pagehide` + `hard:true` + 关 WS | **立即 0** | 同上 |
| 心跳超时 | 500 ms 没收到任何网页指令 | **立即 0** | 网页可能卡死/断网，没人看着车 |
| 前端断连 | WebSocket close（`drop_owner`） | **立即 0** | 同上 |
| 急停 | 网页急停 / `POST /api/estop` | **立即 0 并锁存** | 安全底线，绝不变慢 |
| 固件看门狗 | STM32 800 ms 无合法命令帧 | 固件自己清零 | 硬件兜底 |

> 斜杠前的 `hard:true` 是前端发给后端的标记：`{"t":"cmd","vx":0,"wz":0,"hard":true}`
> 或 HTTP `POST /api/stop {"hard":true}`。它只对“目标为 0”的指令有意义，并会锁存
> 到下一次非零行驶指令，防止随后的 0 心跳把硬停又变回软停。

### 4.3 加减速斜率与软停时间

| 轴 | 加速 | 减速 | 说明 |
|---|---|---|---|
| `vx` | 1.0 m/s² | **0.40 m/s²** | 加速跟手；减速明显更慢，才有“软停”手感 |
| `wz` | 4.0 rad/s² | **1.50 rad/s²** | 同上 |

从 0.30 m/s 松手：`t = v/a = 0.30 / 0.40 = 0.75 s`，停止距离
`s = v²/(2a) = 0.09 / 0.80 = 0.1125 m`（约 11 cm）—— 人能明显看到车“滑一小段”。

各档位满速软停时间 / 距离（固定 DEC，速度越高滑得越远）：

| 档位 | 满速 | 软停时间 `v/DEC` | 软停距离 `v²/(2·DEC)` |
|---|---|---|---|
| 低速 | 0.15 m/s | 0.375 s | 2.8 cm |
| 中速 | 0.30 m/s | 0.75 s | 11 cm |
| 高速 | 0.50 m/s | 1.25 s | 31 cm |
| 快速 | 0.80 m/s | 2.00 s | 80 cm |
| 极速 | 1.20 m/s | 3.00 s | 1.80 m |
| 超快 | 1.60 m/s | 4.00 s | 3.20 m |

> **为什么不再用一个斜率？** 共用 1.0 m/s² 时 0.3 m/s 松手 0.3 s 就停，
> 几乎感觉不到缓停；共用 0.4 m/s² 时起步 0.3 m/s 要 0.75 s，推杆会发肉。
> 所以拆成 `ACC=1.0`（跟手）+ `DEC=0.40`（软停）。真正危险时用急停/超时，
> 那两条路径永远立即归零，不会等这 0.75~4 s。

**软停期间必须继续有网页心跳。** 真实页面在松手后仍按 20 Hz 发 0，所以能走完
整个减速过程；脚本单次 `POST /api/stop` 只会软停 0.5 s，之后 500 ms 心跳超时
按安全层立即归零（这是预期行为，不是 bug）。需要脚本完整软停时，请在减速期间
持续 POST `/api/stop`（自测里的 `hold_stop()` 就是这么做的）。

斜坡关闭时（`/api/ramp {"on":false}`）：加速和停车都恢复旧行为 —— 下一拍直接
阶跃到目标（目标 0 就是立即停），不保留任何减速过程。

> 没有登录/鉴权。**只放在可信局域网**，不要把端口映射到公网。

## 5. 串口协议（与 `firmware/stm32-chassis/user/main.c` 核对过）

### 5.1 命令帧（上位机 → STM32，11 字节，大端）

| 字节 | 含义 |
|---|---|
| 0 | `0x7B` 帧头 |
| 1 | `0`（AutoRecharge，固件忽略） |
| 2 | `0`（SecurityPLY，固件忽略） |
| 3..4 | `vx` int16 BE，mm/s |
| 5..6 | `vy` int16 BE，恒 0（差速车没有横向自由度） |
| 7..8 | `wz` int16 BE，mrad/s |
| 9 | `BCC = XOR([0..8])` |
| 10 | `0x7D` 帧尾 |

按 20~50 Hz 持续发（默认 30 Hz）。STM32 的 `CMD_TIMEOUT_MS = 800`，
超时就 `g_eff_vx=0/g_eff_wz=0`，但**保持使能**（零速主动刹住比失能滑行安全）。
本程序用 500 ms 心跳先归零，所以正常情况看不到固件超时。

### 5.2 上行 24 字节主遥测帧（STM32 → 上位机，20 Hz）

| 字节 | 含义 |
|---|---|
| 0 | `0x7B` |
| 1 | `Flag_Stop`：1 = 当前命令为停止（超时也按停止算） |
| 2..3 | 车体 `vx` int16 BE，mm/s（由左右**实际**轮速正解） |
| 4..5 | `vy`，恒 0 |
| 6..7 | 车体 `wz` int16 BE，mrad/s（实际轮速差速正解） |
| 8..9 / 10..11 / 12..13 | IMU `ax/ay/az` int16 BE，m/s² = raw / **1671.84**（±2g 量程） |
| 14..15 / 16..17 / 18..19 | IMU `gx/gy/gz` int16 BE，rad/s = raw × **0.00026644**（±500 dps） |
| 20..21 | 电池 uint16 BE，mV —— **新底盘无采样，恒 0**（界面显示“—”） |
| 22 | `BCC = XOR([0..21])` |
| 23 | `0x7D` |

> `vx/wz` 是**车体系**：前进为正。IMU 原始值在固件里已从 ±16g/±2000dps 换算到
> 上位机约定的 ±2g/±500dps，所以这里的系数不能改。

### 5.3 上行 44 字节状态帧（STM32 → 上位机，20 Hz）

| 偏移 | 类型 | 缩放/单位 | 含义 | Web 显示 |
|---|---|---|---|---|
| 0 | u8 | — | `0x7E` 帧头 | 不显示（解析用） |
| 1 | u8 | bitfield | flags（见下表） | 底盘标志位卡 |
| 2..3 | i16 BE | ÷1000 → m/s | STM32 **最近一次收到的** vx（不是超时后的 0） | 链路诊断“底盘回读指令” |
| 4..5 | i16 BE | ÷1000 → rad/s | 最近一次收到的 wz | 同上 |
| 6..7 | i16 BE | ÷100 → rad/s | 左**实际** ω（电机原始方向） | 左轮大数字 + 条形图 |
| 8..9 | i16 BE | ÷100 → rad/s | 右实际 ω | 右轮大数字 + 条形图 |
| 10..11 | i16 BE | ÷100 → rad/s | 左**目标** ω（逆解+限幅后的最终值） | 左轮目标/偏差/跟随度 |
| 12..13 | i16 BE | ÷100 → rad/s | 右目标 ω | 右轮目标/偏差/跟随度 |
| 14..15 | i16 BE | ÷100 → Nm | 左扭矩 τ（达妙 12bit T，±40 Nm） | 左轮扭矩 + 趋势条 |
| 16..17 | i16 BE | ÷100 → Nm | 右扭矩 | 右轮扭矩 + 趋势条 |
| 18 | u8 | — | 左 ERR（0 失能 / 1 使能 / 5~E 故障） | ERR 中文 + 红/绿 |
| 19 | u8 | — | 右 ERR | 同上 |
| 20 | u8 | ℃ | 左 MOS 温度 | MOS 温度（>70 橙 / >85 红） |
| 21 | u8 | ℃ | 右 MOS 温度 | 同上 |
| 22 | u8 | ℃ | 左线圈温度 | 线圈温度（>70 橙 / >85 红） |
| 23 | u8 | ℃ | 右线圈温度 | 同上 |
| 24..25 | i16 BE | ÷100 → rad | 左累计位置 | 左轮“累计位置” |
| 26..27 | i16 BE | ÷100 → rad | 右累计位置 | 右轮“累计位置” |
| 28 | u8 | 饱和计数 | CAN 发送失败计数 | 链路“CAN 失败 / 反馈帧” |
| 29 | u8 | 饱和计数 | 反馈帧总数 | 同上 |

| 34..35 | u16 BE | ms | 右反馈年龄 | 右轮“反馈年龄” |
| 36..37 | u16 BE | ms | tick 低 16 位 | IMU 体检行末尾的 `tick` |
| 38 | u8 | — | IMU 扫描到的 I2C 地址（0 = 没扫到） | IMU 提示“地址 0x6A” |
| 39 | u8 | bitfield | IMU 体检：bit0 版本 / bit1 陀螺 / bit2 磁力 / bit7 读到过非零角速度 | IMU 体检 4 个标签 |
| 40 | u8 | — | IMU 版本号主字节 | IMU 体检行“版本” |

| 42 | u8 | — | `BCC = XOR([0..41])` | 不显示（校验用） |
| 43 | u8 | — | `0x7D` 帧尾 | 不显示（解析用） |

flags 位：

| 位 | 含义 |
|---|---|
| bit0 / bit1 | 左 / 右在线 |
| bit2 / bit3 | 左 / 右使能 |
| bit4 | 命令超时（800 ms） |
| bit5 / bit6 | 左 / 右故障（ERR > 1） |
| bit7 | IMU 最近一次读取成功（旧协议是 bit2/3，现在被使能位占用了） |

> **方向**：固件里 `DM_DIR_SIGN = -1`（实测发 `vx=+0.1` 时两轮倒转，所以整体取反）。
> 因此 44 字节帧里的 **ω 和扭矩是电机原始方向**：车前进时 ω 为负；而 24 字节帧的
> `vx/wz` 已乘过方向系数，前进为正。界面按这个约定显示（轮速卡上标注了“前进为负”）。
>
> 命令帧的 `wz` 是**协议值**：`wz > 0` 左转、`wz < 0` 右转。网页的“右推”在
> `static/app.js` 的 `WZ_CMD_SIGN = -1` 处转成负值；服务端和遥测都不再取反（§3.1）。
> 如果实车右推仍左转，先按 §8 检查左右电机 CAN ID/接线是否互换，不要在前端或
> 遥测显示层偷偷翻符号（那会让“实际值”和“指令值”对不上）。

### 5.4 帧同步与 BCC 的实现要点

1. **同步条件**：`上一字节 == 0x7D` 且 `本字节 ∈ {0x7B, 0x7E}` 才当成帧头。
   固件保证按 **先 24 字节、后 44 字节** 的顺序发，所以每个帧头前面都是上一个帧尾。
   单看当前字节会把数据区里的 `0x7B/0x7E` 误认为帧头，加前导约束后误判率大幅下降，
   剩下的靠“帧尾 + BCC”兜底。
2. **长度表**：`0x7B → 24`，`0x7E → 44`。凑够长度才校验。
3. **BCC**：`XOR(frame[0 .. len-3])` 必须等于 `frame[len-2]`，且 `frame[len-1] == 0x7D`。
   失败时**只丢第一个字节**，再从下一字节重新找“前导帧尾 + 帧头”，
   不需要清空缓冲，更不需要复位；丢字节数记在 `link.resync_bytes`，校验失败次数记在
   `link.bad_frames`，界面的“链路诊断”里能直接看到。
4. 跨 `read()` 的前导字节用一个 `prev` 字段保存，所以帧被拆在两次串口读里也能接上。
5. 解析器只用 1 KB 以内的 `bytearray`，**不假设一次 read 正好是一帧**。

`--sim` 模式产生的 24/44 字节帧也走同一个解析器，所以 BCC、帧同步、缩放系数
在 Windows 上就能验证，真机上只剩接线和方向要确认。

> `hard:true` 只对“目标为 0”的安全停车有效（页面隐藏/失焦/关页），

> 脚本直接调 API 时也要注意符号，不要和“驾驶意图（右为正）”混用。

- `ramp.mode`：`accel`（加速）、`decel`（**缓停中**）、`hard`（立即停）、

- `ramp.stopping=true`：正在减速（UI 高亮黄色）。
- `ramp.hard_stop=true`：这次停车是安全停车，实发已强制 0。

关闭缓启缓停后 `tx_*` 会在下一拍直接等于 `target_*`。

## 8. 上车前必须确认的点

1. **串口独占**：`ls -l /dev/wheeltec_controller` 指向 `ttyUSB0`；
   确认没有别的进程（GNSS 驱动、Modbus 轮询、另一个 car_web）在读：
   `sudo fuser -v /dev/ttyUSB0` 或 `lsof /dev/ttyUSB0`。
   本程序会用 TIOCEXCL 独占，占用失败时 `/status` 里能看到原因。
2. **STM32 在跑新固件**：`/status` 能看到 `st` 计数增长、`启动=正常`、`版本=1`；
   若 `tel` 有而 `st` 一直没有，说明固件还是旧版（没有 44 字节帧）。
3. **方向**：低速档轻推前进，确认车真的向前；`DM_DIR_SIGN=-1` 是实测值，
   换电机/换接线后可能又要改（改固件，不改本程序）。同时确认 `wz`：右推应右转。
   网页右推对应串口 `wz < 0`（`static/app.js` 的 `WZ_CMD_SIGN=-1`，见 §3.1）；
   若串口确实是负值但车仍左转，检查左右电机 CAN ID / 接线是否互换（硬件/固件层），
   **不要**在前端或遥测显示层再翻一次。
4. **IMU**：静止时 `az≈9.8`、`ax/ay≈0`、`gz≈0`；右转时 `gz` 应为负、左转为正。
   水平泡偏差大说明模块装歪或坐标轴不同（固件里 `IMU_GYRO_Z_SIGN` 可改）。
5. **里程 / 轮距**：拉尺走 2 m，看界面距离误差；里程来自固件的轮速正解，
   固件里的 `WHEEL_R_M` / `TRACK_WIDTH_M` 才是真值来源。
   **新底盘轮距为 456 mm（0.456 m）**：本目录 `car_web.py` 的
   `TRACK_WIDTH_M` 已改为 0.456，但它只影响 `--sim` 仿真和界面换算；
   `firmware/stm32-chassis/user/main.c` 里的 `TRACK_WIDTH_M` 若仍是 0.425，
   真机转弯/里程仍按旧值算，需要固件维护者同步（本目录不改固件）。
6. **温度/扭矩量程**：固件用的是 DM 出厂默认 `PMAX/VMAX/TMAX`，如果电机被改过量程，
   扭矩/位置读数会按比例失真（速度指令不受影响）。
7. **电池字段**：新底盘没有采样，`bat_mv` 恒 0 是正常的，不要当故障。
8. **急停链路**：网页急停只清零；若需要“切断动力”，还得靠底盘电源/使能，
   本程序不会主动发失能（固件也不发）。
9. **高速档**：先低速跑一遍方向和刹车，再逐步上快速/极速/超快。
   软停是固定 0.40 m/s²，1.6 m/s 满速软停要 4 s / 3.2 m —— **必须在空旷场地**
   测试，并确认前方没有人和障碍物；场地不够就直接按急停（立即归零）。
10. **多标签页**：同时开两个页面会互相覆盖指令（最后发送者生效）。
    只用一个页面控制，其余只看看状态。
11. **网络**：手机与 RK3576 同网段；页面没有鉴权，别暴露到公网。

## 9. 常见问题

- **打开页面一直“未连接服务器”**：确认 `python3 car_web.py` 还在跑、端口对、防火墙放行；
  看终端是否有异常。前端会每 0.5→5 s 退避重连。
- **串口打不开 `Device or resource busy`**：另一个进程占着；`sudo fuser -k /dev/ttyUSB0`
  先停掉它，再重启本程序（本程序会每秒自动重试）。
- **`串口已打开但 1000 ms 没有遥测帧`**：TX/RX 接反、STM32 没上电、波特率不是 115200。
- **车不动但 ω 有目标**：看 flags 的“左/右使能”“命令超时”“故障”；
  ERR>1 时固件不会输出。
- **推前进车后退**：`DM_DIR_SIGN` 的符号问题，改固件；不要在前端偷偷取反，
  否则遥测帧的 `vx` 会和实际相反。
- **右推左转**：先看 `/status` 的“实发 wz”是不是负数、`status.cmd_wz` 是不是同一个负数。
  若已为负仍左转，说明左右轮/左右电机接反（硬件/固件层），按 §8.3 检查；
  不要在 `app.js` 里把 `WZ_CMD_SIGN` 改成 `+1` 来“修”，那会和遥测实际值对不上。
- **缓启缓停关不掉/开了没感觉**：看 `/api/ramp` 的 `mode`：`accel`=加速、
  `decel`=缓停中、`hard`=立即停。松手/回中/停止按钮会显示 `decel`（实发值
  逐拍下降）；急停/超时/页面隐藏是 `hard`（立即 0），属正常。
  如果松手瞬间就变 0，先确认浏览器没有把 `visibilitychange`/`blur` 也当成松手
  （这两个走 hard），以及 `/api/ramp` 的 `on` 是不是被脚本关掉了。
- **单次 curl `/api/stop` 只软停半秒**：正常。500 ms 没收到下一条指令就按心跳
  超时立即归零；要观察完整软停，请在减速期间持续 POST（见 §4.3）。
- **8000 端口被占用**：`--port 8001`；`tools/chassis_web.py` 默认占 8080。
- **中文乱码**：本目录文件均为 UTF-8 无 BOM；若被 Windows PowerShell 5.1
  的 `Get-Content/Set-Content` 改写过，会坏掉，重新 checkout 该目录即可。
