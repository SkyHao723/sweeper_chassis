# 两驱差速小车 —— ESP32 上位机替身 + 网页遥控器

ESP32 这里扮演的是 **Wheeltec 上位机**（`wheeltec_robot_node`）的角色：
把网页上的操作打包成 11 字节速度帧发给 STM32，再把遥测读回来显示。

**所有底盘运算都在 STM32 里**：逆运动学、电机闭环、轮速计里程计、卡尔曼滤波。
ESP32 不做任何运动学计算，只负责联网和显示。

```
手机浏览器 ──WiFi──► ESP32 ──UART2──► STM32 ──CAN1──► 两台 FOC 驱动器
   (上位机替身)                (底盘板: 逆解/闭环/里程计/EKF)
```

## 接线

**ESP32 ↔ STM32**（115200 8-N-1，两边都是 3.3V）

```
ESP32 GPIO17 (TX2)  ->  STM32 PA3 (USART2_RX)
ESP32 GPIO16 (RX2)  <-  STM32 PA2 (USART2_TX)
ESP32 GND           <-> STM32 GND
```

> ESP32 接的是 STM32 的**从口 USART2**。主口 USART1（PA9/PA10）留给
> CH340 / RK3588。两个口跑同一套协议，主口优先级更高，详见 `docs/wiring.md`。
> ESP32 代码里的 `STM32_RX_PIN=16` / `STM32_TX_PIN=17` **不用改**，
> 变的只是 STM32 那一端接到哪个脚。

**ESP32 ↔ OLED**（0.96 寸 SSD1306，4 脚 I2C 版）

```
OLED VCC -> 3V3    OLED GND -> GND    OLED SCL -> GPIO9    OLED SDA -> GPIO8
```

STM32 的 CAN 仍然是 PA11 / PA12 接 CAN 收发器。

## WiFi

```text
SSID:     ZTE-s9yACH
Password: Goodhans@8185311
```

ESP32 工作在 STA 模式，手机连同一个路由器，浏览器打开 OLED 上显示的 IP。

> 经典 ESP32 只支持 2.4GHz。如果这个 SSID 是 5GHz 的，请在路由器上开一个
> 2.4GHz 的并改 `WIFI_SSID`。

## 怎么用

- **▲ ▼** 前进 / 后退（走 `vx`）
- **◀ ▶** 原地左转 / 右转（走 `wz`）
- **■** 急停
- 「速度」滑条 0.10 – 2.10 m/s，「转向」滑条 0.20 – 3.00 rad/s，行驶中改立即生效
- 桌面浏览器支持方向键 / WASD
- **电机 / 水泵** 两个按钮控制 PB0 / PB1 上的继电器（低电平触发），点一下切换，状态由 STM32 锁存
- **■ 急停**会同时刹车 + 断开两个继电器
- 下面那块画布实时画车轮里程计积出来的轨迹，「清空显示」只清画面不动底盘

**松手就刹车。** 按住时网页每 150ms 重发一次；ESP32 在 400ms 没收到遥控请求时
会自己补发零速度（手机锁屏、关页面都算）；STM32 那边 800ms 收不到任何命令
也会自动刹车并断开继电器。三层兜底。

## 协议

沿用 Wheeltec 底盘那套（详见 `docs/chassis-serial-protocol.md`），头 `0x7B`、尾 `0x7D`、
速度 ×1000、BCC 逐字节异或。

### 命令帧 11 字节（ESP32 → STM32）

| 字节 | 含义 |
|---|---|
| 0 | `0x7B` |
| 1 | AutoRecharge |
| 2 | SecurityPLY |
| 3-4 | int16 大端 `vx × 1000` mm/s |
| 5-6 | int16 大端 `vy × 1000` mm/s（差速车恒 0）|
| 7-8 | int16 大端 `wz × 1000` mrad/s |
| 9 | BCC = `[0]^[1]^...^[8]` |
| 10 | `0x7D` |

### 主遥测帧 24 字节（STM32 → ESP32，标准帧）

| 字节 | 含义 |
|---|---|
| 0 / 1 | `0x7B` / Flag_Stop |
| 2-3 / 4-5 / 6-7 | 车体 vx mm/s / vy mm/s / wz mrad/s |
| 8-19 | IMU 六轴原始值（**现在全 0，装了 IMU 才有**）|
| 20-21 | 电池电压 mV（来自驱动器定时上报帧）|
| 22 / 23 | BCC = `[0..21]` / `0x7D` |

### 里程计帧 34 字节（STM32 → ESP32，本工程扩展，头 `0x7E`）

因为位姿在 STM32 算，标准帧里没有位置，所以加了这个扩展帧。

| 字节 | 含义 |
|---|---|
| 0 / 1 | `0x7E` / flags（bit0 里程计有效 / bit1 看门狗停车 / bit2 曾收到命令）|
| 2-5 / 6-9 | int32 大端 x mm / y mm |
| 10-11 | int16 大端 航向角，单位 **0.01 度** |
| 12-13 / 14-15 | 滤波后 vx mm/s / wz mrad/s |
| 16-17 / 18-19 | 左轮 / 右轮 **物理**转速 RPM |
| 20-21 / 22-23 | 左轮 / 右轮 目标转速 RPM |
| 24 / 25 | 1号 / 2号 驱动器故障码 |
| 26 / 27 / 28 / 29 | CAN 错误 / 坏帧 / 有效命令 / 串口溢出 |
| 30 | **继电器状态**（bit0 电机 bit1 水泵）|
| 31 | 预留 |
| 32 / 33 | BCC = `[0..31]` / `0x7D` |

### 功能帧（复用 11 字节命令帧，靠 `f[1]` 功能码区分）

协议里本来就有这个做法（`0x04` 灯带 / `0x01` 回充开关 / `0x00` 安全防护），
本工程占用了空闲的 **`0x05`** 做继电器控制：

| 字节 | 含义 |
|---|---|
| 0 | `0x7B` |
| 1 | `0x05`（功能码）|
| 2 | 继电器掩码：bit0 电机继电器，bit1 水泵继电器 |
| 3-8 | 0 |
| 9 / 10 | BCC / `0x7D` |

STM32 会**锁存**这个状态，不需要周期重发。网页用 `/api/relay?mask=N` 一次下发整帧，
不按位改——否则急停要同时关两个继电器时，两个请求会互相覆盖。

## 底盘运算（在 STM32 里）

**车体参数**（`firmware/stm32-chassis/user/main.c` 顶部）

```c
#define WHEEL_DIAMETER_MM   205.0f   /* 车轮直径 */
#define TRACK_WIDTH_MM      930.0f   /* 左右轮触地间距 */
```

**逆解**（车体速度 → 轮速）

```
v_left  = vx - wz · b/2
v_right = vx + wz · b/2
RPM     = v / (π·D) · 60
```

**里程计 + 卡尔曼**：50Hz。6 状态扩展卡尔曼滤波

```
x = [ X, Y, θ, v, ω, b_gz ]
```

- 预测：用当前 `v, ω` 推位姿
- 观测 1（一直有）：轮速正解出的 `(v, ω)`
- 观测 2（**预留**）：陀螺仪 `gz`，同时估计零偏 `b_gz`

轮速计报的是**累计里程**而不是瞬时转速，所以上位机的时间抖动完全影响不到航迹；
`dt` 只用在 EKF 的速度观测上。

## 外设继电器

STM32 上用两个 GPIO 驱动继电器模块：

```
PB0 -> 电机继电器 IN
PB1 -> 水泵继电器 IN
5V  -> 继电器模块 VCC      <-- 从本板取, 别用独立电源
GND -> 继电器模块 GND      <-- 同上, 必须共地
```

### ⚠️ 接线铁律：必须共地、共电源

**模块的 VCC/GND 一定要和 STM32 用同一个电源参考**，最省事就是直接从本板引
5V 和 GND。

我们踩过这个坑：一开始用独立 5V 给继电器模块供电（没共地），光耦的输入回路
`模块VCC → 光耦 → 1k → IN → STM32引脚 → STM32 GND → 模块GND` 没有稳定的返回
路径，驱动电流时有时无 → 光耦半开 → 驱动三极管工作在放大区 → **线圈半通电，
继电器持续嗡嗡响**（不是吸合也不是释放，卡在中间）。

改成从本板取 5V/GND 后立刻正常。**线也要短、要粗**——即使接了地，细长线上的
几 mA 返回电流也会在 GND 上压出波动，造成同样的半驱动。

> 这个症状和"触发电平不对"很容易混淆。**先量供电和地，再怀疑电平。**

### 触发电平：低电平触发（本车实测）

| 模块类型 | IN 低 | IN 高 |
|---|---|---|
| **低电平触发**（本车模块）| **导通** | 断开 |
| 高电平触发 | 断开 | **导通** |

```c
#define RELAY_MOTOR_PIN     GPIO_Pin_0   /* PB0 */
#define RELAY_PUMP_PIN      GPIO_Pin_1   /* PB1 */
#define RELAY_PORT          GPIOB
#define RELAY_ACTIVE_LOW    1            /* 1=低电平触发(实测), 0=高电平触发 */
#define RELAY_OFF_ON_LINK_LOSS  1        /* 链路断了自动断开两个继电器 */
```

模块上有 `H`/`L` 跳线的话拨到 **L**。

**换模块后如果网页上"开/关"反了，只改 `RELAY_ACTIVE_LOW` 这一个值就行。**

> 顺带记一下为什么选低电平触发（3.3V 单片机 + 5V 模块）：
> 低电平触发时驱动电流从**模块自己的 5V** 灌下来（约 3.8mA），STM32 只负责
> 把引脚拉到 0V，余量比高电平触发靠 3.3V 往外供（约 2.1mA）大。
>
> 理论推导只能算个大概——光耦 LED 的实际压降、串联电阻大小、有没有输入级
> 三极管都会改变结论。**最终以实测为准**，所以我们当时是用跳线直接试出来的。

### 其他注意

- 想换引脚就改前两行——只要别撞上 STM32 的 PA2/PA3（本口）、PA9/PA10（主口）、
  PA11/PA12（CAN）、PB6/PB7（OLED 软件 I2C，未使用）。
- 低电平触发时，复位那一瞬间 IN 会被模块的 5V 经光耦抬到约 3.8V，往引脚灌进
  约 1mA。这在 STM32 规格内（注入电流限值 ±5mA），且只持续约 1ms，可以忽略。
- 如果吸合不可靠（"嗒"一声但触点没闭合），是 3.3V 驱动 5V 模块的通病：
  换 3.3V 兼容模块最省事，或者把模块上那个串联电阻改小到 470Ω 左右。
- 继电器线圈约 80mA 是走 **5V** 的，别接到 3.3V。
- 裸继电器（非模块）记得线圈两端并一个 1N4148/1N4007 续流，否则反峰容易打坏 IO。

`RELAY_OFF_ON_LINK_LOSS` 设 1 时，看门狗（800ms 收不到命令）会连同电机一起把
两个继电器断开。水泵无人看管会一直喷水，所以默认是开的；想让它保持运行就设 0。

## 以后加 IMU

STM32 里已经留好了接口，就一个函数（`firmware/stm32-chassis/user/main.c` 的 `IMU_ReadGyroZ`）：

```c
static uint8_t IMU_ReadGyroZ(float *gz)
{
    (void)gz;
    return 0;        /* 返回 0 -> EKF 自动跳过陀螺仪那一步, 只用轮速计 */
}
```

装上之后把它改成读一次陀螺仪 Z 轴角速度（rad/s，逆时针为正）并 `return 1` 即可，
卡尔曼滤波会自动开始融合并估计零偏。例如：

```c
int16_t raw = IMU_ReadReg16(GYRO_ZOUT_H);
*gz = raw / 65.5f * 0.0174533f;     /* ±500dps 量程 -> rad/s */
return 1;
```

状态帧里 IMU 那 12 个字节现在是 0，到时候一并填上原始值就行。

> 注意：STM32 工程里已有的 `hardware/OLED.c` 用的是 PB6/PB7 软件 I2C。
> 如果 IMU 也挂这条总线，建议把 OLED 一起换成硬件 I2C1（同样是 PB6/PB7），
> 软件 I2C 读写 IMU 寄存器会很别扭。

## 调参

滤波参数都在 `firmware/stm32-chassis/user/main.c` 里：

| 宏 | 作用 | 调大的后果 |
|---|---|---|
| `EKF_SIGMA_V` | 轮速线速度噪声 | 更信轮速，`v` 跟随更快、更抖 |
| `EKF_SIGMA_W` | 轮速角速度噪声 | 更信轮速转向 |
| `EKF_SIGMA_GZ` | 陀螺仪噪声 | 更信陀螺仪（IMU 来了才有效）|
| `EKF_SLIP_DIST` | 每米位置不确定度 | 更信观测、更容易被轮速带跑 |
| `EKF_SLIP_ANG` | 每弧度航向不确定度 | 同上 |
| `EKF_BIAS_WALK` | 陀螺零偏游走 | 零偏估计更活、更抖 |

**航向漂移怎么办**：先量准 `TRACK_WIDTH_MM`（拿卷尺量两轮触地中心距，不要量外壳）。
航向误差和轮距基本成正比。车轮直径量不准就直线推 5 米，看里程计报了多少米，按比例修。

## 排查

| 现象 | 说明 |
|---|---|
| 有效命令一直 0 | STM32 没收到帧 —— 查 TX/RX 接反、共地 |
| 坏帧一直涨 | 收到了但 BCC 不过 —— 查波特率 |
| 串口溢出不是 0 | STM32 收不过来（正常应为 0）|
| 目标 RPM 有值但实测一直 0 | 驱动器没使能 / 没上功率电 / 电机 ID 不对 |
| 1号/2号 故障不为 0 | 驱动器报故障，故障码见协议文档第 11 页 |
| 能走但航向乱飘 | 轮距或轮径参数不准，先量准再调 |
| 推车时里程计不动 | 正常，驱动器没回码时按 0 处理，见 `RPM_STALE_MS` |

## 和前一版相比去掉了什么

- **手动发 CAN 帧**的功能没了。STM32 现在只认标准速度帧，不再接受原始 CAN 透传，
  要保持协议干净。要调试 CAN 请用 `FOC-windows-APP` 或 CAN 分析仪。
- ESP32 不再做差速混控，改成发 `(vx, wz)`；混控在 STM32。
