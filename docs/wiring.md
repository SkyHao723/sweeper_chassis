本文是 STM32 底盘板 + ESP32 上位机替身这两块板子的完整接线说明。
所有引脚都从当前固件源码里核对过，不是凭记忆写的。

对应代码：

- STM32：`firmware/stm32-chassis/user/main.c`
- ESP32：`firmware/esp32-web-host/esp32-web-host.ino`

## 1. ⚠️ 电源与地（先看这条）

**所有板子必须共地。** 这是最容易出问题、也最难排查的地方——不共地会导致
信号"半驱动"（我们已经在继电器上踩过一次，表现为持续嗡嗡响）。

| 板子 | 供电 | 说明 |
|---|---|---|
| STM32 (Blue Pill) | 5V 脚 或 USB | 板载 AMS1117 转 3.3V 给芯片 |
| ESP32 开发板 | 5V/VIN 脚 或 USB | |
| CAN 收发器 | 见第 3 节 | TJA1050 要 5V，SN65HVD230 要 3.3V |
| 继电器模块 ×2 | **STM32 板上的 5V** | 别用独立电源，否则要额外共地 |
| OLED | ESP32 的 3V3 | |
| FOC 驱动器 ×2 | 电池/功率电源 | 和逻辑电源共地 |

**推荐做法**：整套用一个电源（比如电池经 DC-DC 出 5V），分给 STM32、ESP32、
CAN 收发器、继电器模块。这样共地天然成立。

**如果必须分开供电**：所有 GND 必须用导线连在一起，而且要短、要粗。

## 2. 双串口：CH340(RK3588) + ESP32

两个串口跑**同一套协议**，主口优先级更高、可以随时抢占；从口只能在主口空闲时接管。

| 口 | 引脚 | 接谁 | 角色 | 波特率 |
|---|---|---|---|---|
| **USART1** | **PA9 (TX) / PA10 (RX)** | **CH340 → RK3588** | **主口** | 115200 |
| USART2 | PA2 (TX) / PA3 (RX) | ESP32 | 从口（临时调试）| 115200 |

### TX/RX 交叉接（重点，最容易接反）

**规则：TX 接对方的 RX。**

| 对端 | 接 STM32 | 原因 |
|---|---|---|
| CH340 **TX** | **PA10** | PA10 = USART1_RX，STM32 负责"收" |
| CH340 **RX** | **PA9** | PA9 = USART1_TX，STM32 负责"发" |
| CH340 **GND** | GND | 必须 |
| CH340 **VCC** | **不接** | TTL 自己从 USB 取电，接了会倒灌 |

TTL 模块上的 3.3V/5V 电平跳线拨到 **3.3V**。

ESP32 那边同理：

| ESP32 | 接 STM32 |
|---|---|
| GPIO17 (TX2) | **PA3**（USART2_RX）|
| GPIO16 (RX2) | **PA2**（USART2_TX）|
| GND | GND |

> 接反的症状：网页上「有效命令」一直是 0。

### 为什么主口放 USART1

长期上位机是 RK3588，直接接 PA9/PA10。等 ESP32 调试完摘掉，**接线和代码都不用再动**。
反过来（CH340 接 PA2/PA3）的话，以后要搬线 + 改代码里主从口的角色。

### 控制权仲裁

两个口都能发速度帧，规则是：

1. 只有**非零**速度帧才抢控制权（零速度是停车/心跳，不抢）
2. **主口随时可以抢**；从口只能在主口不是控制方、或主口控制权已超时时才拿
3. 控制权 **500ms** 不刷新就释放
4. 不是控制方的速度帧**直接丢弃**
5. **看门狗只认控制方的帧** —— 否则从口的心跳会把看门狗一直喂着，主口掉线了车也不会停
6. 继电器是锁存式开关，**两个口随时可操作**，不参与仲裁

实际效果：RK3588 一跑起来就自动接管（Nav2 约 12Hz 持续发），它不在的时候 ESP32 照常用。
网页上「**控制方**」会显示当前谁在开车。

## 3. STM32 ↔ CAN 收发器 ↔ 驱动器

STM32 的 CAN1 用的是 **PA11 / PA12**，这两个脚是 CAN 控制器的 TTL 侧，
**不能直接接 CAN_H/CAN_L**，中间必须有收发器。

| STM32 | 方向 | 收发器 | 常见丝印 |
|---|---|---|---|
| PA12 (CAN1_TX) | ──► | TXD / CTX / D | 发送 |
| PA11 (CAN1_RX) | ◄── | RXD / CRX / R | 接收 |
| 5V 或 3V3 | ─── | VCC | 见下面注意 |
| GND | ─── | GND | |

收发器输出侧接驱动器：

```
收发器 CANH ──── 驱动器 CANH ──── 2号驱动器 CANH
收发器 CANL ──── 驱动器 CANL ──── 2号驱动器 CANL
```

**总线参数**（来自驱动器协议文档）

| 项目 | 值 |
|---|---|
| 波特率 | 500 kbps |
| 帧格式 | 扩展帧（29 位 ID）+ 8 字节数据 |
| 终端电阻 | 120 Ω |

**关于 120Ω 终端电阻**：CAN 总线两端各需要一个 120Ω。整条总线**总共两个**，
不是每个节点一个。如果两个 FOC 驱动器已经各带一个，且它们分别在总线两端，
就不用再加；如果 STM32 节点在总线末端，就在这一端并一个 120Ω。

> ⚠️ **收发器型号要选对**：TJA1050 / MCP2551 是 **5V** 器件，它们的 RXD 输出
> 是 5V 电平，直接接 STM32 的 PA11 有风险（PA11/PA12 是 USB 脚，不是 5V 容忍）。
> **STM32F103 推荐用 3.3V 的 SN65HVD230**，供电和电平都匹配，可以直接连。
> 如果手上只有 TJA1050，串一个电阻分压或加电平转换再进 PA11。

**电机 ID**（驱动器外壳上会标）

| 电机 | 控制帧 ID | 回码 ID | 定时上报 ID |
|---|---|---|---|
| 1 号 | `0x1101E600` | `0x1101E601` | `0x1101E603` |
| 2 号 | `0x1201E600` | `0x1201E601` | `0x1201E603` |

## 4. 继电器（PB0 / PB1）

```
PB0 ──► 电机继电器 IN
PB1 ──► 水泵继电器 IN
5V  ──► 两个模块的 VCC
GND ──► 两个模块的 GND
```

| 项目 | 值 |
|---|---|
| 触发电平 | **低电平触发**（IN 给低 → 吸合）|
| 跳线 | 模块上有 H/L 跳线的话拨到 **L** |
| 供电 | 从 STM32 板上取 5V 和 GND |

改引脚改 `firmware/stm32-chassis/user/main.c` 这两行：

```c
#define RELAY_MOTOR_PIN     GPIO_Pin_0      /* PB0 */
#define RELAY_PUMP_PIN      GPIO_Pin_1      /* PB1 */
```

> 继电器线圈约 80mA 走 **5V**，别接 3.3V。
> 换模块后如果网页上"开/关"反了，改 `RELAY_ACTIVE_LOW` 一个值即可。

## 5. OLED（挂在 ESP32 上）

0.96 寸 SSD1306，**4 脚 I2C 版**，地址 `0x3C`。只用来显示自己的 IP 地址。

| OLED | ESP32 |
|---|---|
| VCC | 3V3 |
| GND | GND |
| SCL | GPIO9 |
| SDA | GPIO8 |

代码位置：

```c
static const int OLED_SDA_PIN = 8;
static const int OLED_SCL_PIN = 9;
#define OLED_I2C_ADDRESS 0x3C
```

> ⚠️ **如果你的 ESP32 是 WROOM-32 模组**，GPIO6–11 内部连着 SPI Flash，
> GPIO8/9 有可能不可用（表现为 OLED 全黑）。标准 I2C 脚是 **GPIO21(SDA) / GPIO22(SCL)**。
> 先确认 OLED 真的显示了 IP；没显示就把这两行改成 21/22 并重新接线。

## 6. I2C / IMU（预留，还没接）

IMU 挂 **STM32 的 I2C2**，因为卡尔曼滤波在 STM32 里跑，挂 ESP32 反而要多一趟串口。

### 四根线

| STM32 | 方向 | IMU 模块 | 说明 |
|---|---|---|---|
| **PB10** | ──► | SCL | I2C2 时钟，主机驱动 |
| **PB11** | ◄─► | SDA | I2C2 数据，双向 |
| **3V3** | ─── | VCC | **必须 3.3V**，见下面的警告 |
| **GND** | ─── | GND | |

```
   STM32                    IMU 模块
   PB10 ──────────────────── SCL
   PB11 ──────────────────── SDA
   3V3  ──────────────────── VCC
   GND  ──────────────────── GND
```

板上找丝印 `PB10` / `PB11` 就行，Blue Pill 两排排针都引出来了。

### 上拉电阻

I2C 是开漏总线，**必须要上拉**（STM32 内部那个约 40k 太弱，I2C 要 4.7k 量级）。

- **大多数 IMU 模块（MPU6050 / ICM42688 的成品小板）已经板载 4.7k 上拉，直接接就行。**
- 如果是裸芯片或没带上拉的模块，自己在 SDA 和 SCL 各加一个 **4.7k 到 3V3**。
- **一条总线只要一组上拉**。以后要是把 OLED 也挂到这条总线上，注意别让两边的
  4.7k 并联成 2.35k——一般还能用，但如果哪个模块用的是 2.2k，并联后 1.1k 就偏强了，
  到时候摘掉一组。

### ⚠️ 供电一定要 3.3V

**VCC 接 3V3，不要接 5V。**

原因：模块的 I2C 上拉电阻通常是拉到模块自己的 VCC 上的。你给 5V，上拉就把 SDA/SCL
拉到 5V，等于往 STM32 的 PB10/PB11 灌 5V。虽然 F1 的 I2C 脚大概率是 5V 容忍的，
但没必要冒这个险——而且 MPU6050 这类芯片本身就是 3.3V 器件。

> GY-521（MPU6050 小板）标称支持 5V，是因为板上有 LDO。但用 3.3V 单片机时应该
> 直接喂 3.3V，让它内部 LDO 旁路掉，上拉也落在 3.3V 上。

### 模块上的其他引脚

| 引脚 | 怎么接 |
|---|---|
| AD0 / ADO | **接 GND** → 地址 `0x68`（MPU6050 默认）。接 3V3 → `0x69` |
| INT | 暂时不接。以后想做中断采样再说 |
| XDA / XCL | 辅助 I2C，不接 |
| CS | 不接（接地会切到 SPI 模式）|

### 以后想把 OLED 也挪到 STM32

PB10/PB11 这条总线**能同时挂两个**，地址不冲突：

| 设备 | 地址 |
|---|---|
| SSD1306 OLED | `0x3C` |
| MPU6050 | `0x68` |

接法就是把 OLED 的 SCL/SDA 并到同一条总线，VCC 接 3V3。**但要注意上拉别叠太多。**

### 怎么验证接对了

STM32 里接口已经预留好（`firmware/stm32-chassis/user/main.c` 的 `IMU_ReadGyroZ()`），填上读数后：

- 24 字节标准遥测帧的 **IMU 六轴**字段（偏移 8–19）现在恒为 0，接好后会变成真实原始值
- 网页上如果把这些字段显示出来，数值会随板子晃动而变化 → 说明通了
- 如果一直全 0 或全 `0xFFFF` → 上拉没接 / 地址不对 / 供电不对

## 7. 引脚占用总表

### STM32（STM32F103C8，LQFP48）

| 引脚 | 功能 | 连接 |
|---|---|---|
| PA2 | USART2_TX | → ESP32 GPIO16 (RX2) |
| PA3 | USART2_RX | ← ESP32 GPIO17 (TX2) |
| PA9 | USART1_TX | → CH340 RX |
| PA10 | USART1_RX | ← CH340 TX |
| PA11 | CAN1_RX | ← CAN 收发器 RXD |
| PA12 | CAN1_TX | → CAN 收发器 TXD |
| PB0 | GPIO 输出 | → 电机继电器 IN |
| PB1 | GPIO 输出 | → 水泵继电器 IN |
| PB10 | I2C2_SCL | → IMU SCL（预留）|
| PB11 | I2C2_SDA | → IMU SDA（预留）|
| 5V | 电源 | 供电输入 / 给继电器模块 |
| 3V3 | 电源 | 板载稳压输出 / 给 IMU |
| GND | 地 | 必须和 CH340、ESP32、收发器共地 |

**内部占用（不占外部引脚）**：TIM2 做 1ms 时基、SysTick 给 `Delay_ms/us` 用。

**其他空闲的 I2C 备选**：I2C1 在 PB6/PB7（`hardware/OLED.c` 占着做软件 I2C，未调用）；
I2C1 重映射在 PB8/PB9（但那两个也是 CAN1 的重映射脚，留着）。

### ESP32

| 引脚 | 功能 | 连接 |
|---|---|---|
| GPIO16 | UART2 RX | ← STM32 PA2 |
| GPIO17 | UART2 TX | → STM32 PA3 |
| GPIO8 | I2C SDA | → OLED SDA |
| GPIO9 | I2C SCL | → OLED SCL |
| 5V/VIN | 电源 | 供电输入 |
| 3V3 | 电源 | 给 OLED |
| GND | 地 | 必须和 STM32 共地 |

> ESP32 的 GPIO16/17 在代码里不用改（还是 `STM32_RX_PIN=16` / `STM32_TX_PIN=17`），
> 只是**在 STM32 那一端从 PA9/PA10 挪到了 PA2/PA3**。

## 9. 上电检查顺序

按这个顺序最省时间：

1. **不接任何负载**（电机、水泵都摘掉），只上电
2. 听继电器——**不应该有任何吸合声或嗡嗡声**
   - 有嗡嗡声 → 先查继电器模块的 VCC/GND 是不是和 STM32 同一路电源、有没有共地
3. 打开网页，看「有效命令」这个数在不在涨
   - 一直是 0 → 串口 TX/RX 接反了，或者没共地（先查 PA2/PA3 那两根）
   - 在涨 → 串口通了
4. 看「坏帧」在不在涨
   - 一直涨 → 波特率不对（应该是 115200）
5. 按 ▲，看「左轮/右轮 目标」有没有出现数值
6. 有目标值但「实测」一直是 0 → 驱动器没使能 / 没上功率电 / CAN 线接反 / 电机 ID 不对
7. 一切正常后再接电机负载，最后接水泵

**接 CH340 / RK3588 时**：主口一发非零命令就会抢走控制权，网页上的「控制方」会变成
「主口(RK3588)」。想让 ESP32 重新接管，把主口那边停掉等 500ms 就行。

## 10. 网页上能看到什么（排查用）

| 显示项 | 含义 |
|---|---|
| STM32 在线 / 离线 | 串口链路是否正常（600ms 内有遥测）|
| 有效命令 | STM32 收到的合法帧数，一直在涨说明串口通 |
| 坏帧 | 收到了但 BCC 不过，通常是波特率问题 |
| 串口溢出 | STM32 收不过来，正常应该是 0 |
| **控制方** | 当前谁在开车：无 / 主口(RK3588) / ESP32 |
| 左轮/右轮 实测/目标 | 目标给上了但实测不动 = 驱动器侧问题 |
| 1号/2号故障 | 驱动器故障码，对照协议文档第 11 页 |
| 状态 | 「看门狗停车」说明 800ms 没收到命令，底盘自动刹车了 |
