# 接线总表

本文是 **STM32 底盘板**的完整接线说明。所有引脚都从当前固件源码里核对过，
不是凭记忆写的。

对应代码：`firmware/stm32-chassis/user/main.c`

---

## 0. 系统总览

```
   ┌──────────┐  USB 115200  ┌──────────────┐   CAN1 500k   ┌──────────┐
   │  RK3588  │◄────────────►│    STM32     │◄─────────────►│ CAN收发器 │
   │ (上位机)  │  PA9/PA10    │  (底盘板)     │   PA11/PA12   │          │
   └──────────┘              └──┬────────┬──┘               └────┬─────┘
                                │        │                       │ CANH/CANL
                                ▼        ▼                       ▼
                         ┌──────────┐ ┌──────────┐        ┌────────────────┐
                         │电机继电器 │ │水泵继电器 │        │  FOC 驱动器 ×2  │
                         │  (PB0)   │ │  (PB1)   │        │ 1号 / 2号电机   │
                         └──────────┘ └──────────┘        └────────────────┘

                      PB10/PB11 ──── 亚博 YbImu（软件 I2C）
```

> 曾经有一块 ESP32 当临时上位机（走 PA2/PA3），已废弃。**PA2/PA3 现在空着**，
> STM32 也不再初始化 USART2。

## 1. ⚠️ 电源与地（先看这条）

**所有板子必须共地。** 这是最容易出问题、也最难排查的地方——不共地会导致
信号"半驱动"（我们已经在继电器上踩过一次，表现为持续嗡嗡响）。

| 板子 | 供电 | 说明 |
|---|---|---|
| STM32 (Blue Pill) | 5V 脚 或 USB | 板载 AMS1117 转 3.3V 给芯片 |
| CAN 收发器 | 见第 3 节 | TJA1050 要 5V，SN65HVD230 要 3.3V |
| 继电器模块 ×2 | **STM32 板上的 5V** | 别用独立电源，否则要额外共地 |
| YbImu | STM32 的 **3V3** | 绝对不能给 5V，见第 5 节 |
| FOC 驱动器 ×2 | 电池/功率电源 | 和逻辑电源共地 |

**推荐做法**：整套用一个电源（比如电池经 DC-DC 出 5V），分给 STM32、
CAN 收发器、继电器模块。这样共地天然成立。

**如果必须分开供电**：所有 GND 必须用导线连在一起，而且要短、要粗。

## 2. 串口：CH340 / RK3588（USART1）

只有一个串口：**USART1，PA9 (TX) / PA10 (RX)，115200 8N-1**。

### TX/RX 交叉接（重点，最容易接反）

**规则：TX 接对方的 RX。**

| 对端 | 接 STM32 | 原因 |
|---|---|---|
| CH340 **TX** | **PA10** | PA10 = USART1_RX，STM32 负责"收" |
| CH340 **RX** | **PA9** | PA9 = USART1_TX，STM32 负责"发" |
| CH340 **GND** | GND | 必须 |
| CH340 **VCC** | **不接** | TTL 自己从 USB 取电，接了会倒灌 |

TTL 模块上的 3.3V/5V 电平跳线拨到 **3.3V**。

> 接反的症状：诊断脚本里「有效命令」（`ok`）一直是 0。

### 看门狗

STM32 如果 **800ms** 没收到合法命令，就自动刹车并断开电机/水泵继电器。
上位机只要持续发（正常导航约 10~20Hz）就不会触发。

## 3. STM32 ↔ CAN 收发器 ↔ 驱动器

STM32 的 CAN1 用的是 **PA11 / PA12**，这两个脚是 CAN 控制器的 TTL 侧，
**不能直接接 CAN_H/CAN_L**，中间必须有收发器。

| STM32 | 方向 | 收发器 | 常见丝印 |
|---|---|---|---|
| PA12 (CAN1_TX) | ──► | TXD / CTX / D | 发送 |
| PA11 (CAN1_RX) | ◄── | RXD / CRX / R | 接收 |
| 5V 或 3V3 | ─── | VCC | 见下面注意 |
| GND | ─── | GND | |

收发器输出侧接驱动器：

```
收发器 CANH ──── 1号驱动器 CANH ──── 2号驱动器 CANH
收发器 CANL ──── 1号驱动器 CANL ──── 2号驱动器 CANL
```

**总线参数**（来自驱动器协议文档）

| 项目 | 值 |
|---|---|
| 波特率 | 500 kbps |
| 帧格式 | 扩展帧（29 位 ID）+ 8 字节数据 |
| 终端电阻 | 120 Ω |

**关于 120Ω 终端电阻**：CAN 总线两端各需要一个 120Ω。整条总线**总共两个**，
不是每个节点一个。如果两个 FOC 驱动器已经各带一个，且它们分别在总线两端，
就不用再加；如果 STM32 节点在总线末端，就在这一端并一个 120Ω。

> ⚠️ **收发器型号要选对**：TJA1050 / MCP2551 是 **5V** 器件，它们的 RXD 输出
> 是 5V 电平，直接接 STM32 的 PA11 有风险（PA11/PA12 是 USB 脚，不是 5V 容忍）。
> **STM32F103 推荐用 3.3V 的 SN65HVD230**，供电和电平都匹配，可以直接连。
> 如果手上只有 TJA1050，串一个电阻分压或加电平转换再进 PA11。

**电机 ID**（驱动器外壳上会标）

| 电机 | 控制帧 ID | 回码 ID | 定时上报 ID |
|---|---|---|---|
| 1 号 | `0x1101E600` | `0x1101E601` | `0x1101E603` |
| 2 号 | `0x1201E600` | `0x1201E601` | `0x1201E603` |

## 4. 继电器（PB0 / PB1）

```
PB0 ──► 电机继电器 IN
PB1 ──► 水泵继电器 IN
5V  ──► 两个模块的 VCC
GND ──► 两个模块的 GND
```

| 项目 | 值 |
|---|---|
| 触发电平 | **低电平触发**（IN 给低 → 吸合）|
| 跳线 | 模块上有 H/L 跳线的话拨到 **L** |
| 供电 | 从 STM32 板上取 5V 和 GND |

改引脚改 `firmware/stm32-chassis/user/main.c` 这两行：

```c
#define RELAY_MOTOR_PIN     GPIO_Pin_0      /* PB0 */
#define RELAY_PUMP_PIN      GPIO_Pin_1      /* PB1 */
```

> 继电器线圈约 80mA 走 **5V**，别接 3.3V。
> 换模块后如果开关反了，改 `RELAY_ACTIVE_LOW` 一个值即可。
> 链路断开时是否顺手断开继电器由 `RELAY_OFF_ON_LINK_LOSS` 控制。

## 5. IMU：亚博 YbImu（I2C）

型号：**亚博 (Yahboom) YbImu 姿态传感器**，I2C 接口。

### 四根线

| STM32 | 方向 | IMU 模块 | 说明 |
|---|---|---|---|
| **PB10** | ──► | SCL | 时钟，主机驱动 |
| **PB11** | ◄─► | SDA | 数据，双向 |
| **3V3** | ─── | VCC | **必须 3.3V**，见下面的警告 |
| **GND** | ─── | GND | |

```
   STM32                    YbImu
   PB10 ──────────────────── SCL
   PB11 ──────────────────── SDA
   3V3  ──────────────────── VCC
   GND  ──────────────────── GND
```

板上找丝印 `PB10` / `PB11` 就行，Blue Pill 两排排针都引出来了。

### 器件参数（来自 YbImuLib 源码）

| 项目 | 值 |
|---|---|
| I2C 从机地址 | **`0x23`** |
| 寄存器地址宽度 | 1 字节 |
| 数据字节序 | **小端**（底盘协议是大端，驱动里已做交换）|
| `0x04` 原始加速度 | 6 字节 int16×3，单位 g，满量程 **±16g** |
| `0x0A` 原始角速度 | 6 字节 int16×3，单位 rad/s，满量程 **±2000dps** |
| `0x70` | 校准 |
| `0x01` 版本号 | 3 字节 |

### ★ 加速度和陀螺仪必须分两次读

**寄存器指针不会跨功能块自动递增。** `0x04` 那块是 6 字节（`0x04`~`0x09`），
下一块从 `0x0A` 重新开始 —— 所以「从 `0x04` 一次读 12 字节」是错的。

踩过的坑：一开始就是这么写的，结果**加速度正常、陀螺仪恒为 0**，
查了很久才发现是读法问题，不是硬件问题。现在 `YbImu_ReadMotion()` 是
两次独立的 6 字节读。

### ★ 为什么要做量程换算

底盘协议（MD 5.1 节）要求上报的 IMU 原始值必须是 **±2g / ±500dps** 量程下的值，
因为上位机是用**固定系数**换算的：

```
加速度：原始值 / 1671.84    = m/s²
陀螺仪：原始值 × 0.00026644 = rad/s
```

而 YbImu 的原始输出是 **±16g / ±2000dps**。所以 STM32 里必须先还原成 g / rad·s⁻¹，
再按协议量程换算回原始值：

```c
#define IMU_ACCEL_G_TO_RAW  (9.80665f * 1671.84f)   /* g      -> ±2g    原始值 */
#define IMU_GYRO_TO_RAW     (1.0f / 0.00026644f)    /* rad/s  -> ±500dps 原始值 */
```

**搞错量程不会报错，只会让上位机拿到的数全错**（1g 会被算成 0.125g）。
换算后做了限幅：超过 ±2g / ±500dps 的量夹在极值，不会回绕成负的。

### 上拉电阻

I2C 是开漏总线，必须有上拉。**YbImu 模块通常板载了上拉**，直接接就行。
如果读不到，量一下 SDA/SCL 对 3V3 的电阻；没有上拉就自己补两个 **4.7k 到 3V3**。

### ⚠️ 供电一定要 3.3V

**VCC 接 3V3，不要接 5V。**

模块的 I2C 上拉通常拉到它自己的 VCC 上。给 5V 会把 SDA/SCL 拉到 5V，
等于往 STM32 的 PB10/PB11 灌 5V。

### 为什么用软件 I2C 而不是硬件 I2C2

STM32F103 的 I2C 外设有**已知 errata**，某些情况下会死锁；而 ST 标准库的
`I2C_CheckEvent()` 是**无超时的忙等**——一旦卡住整个固件就挂死，表现成
"STM32 突然没反应了"。位翻转没有状态机，好调也好救，而且 50Hz 读这点量完全无所谓。

所以 `hardware/YbImu.c` 是位翻转实现，用 PB10/PB11 的**开漏输出**，
带 SCL 时钟拉伸超时检测。

### 怎么验证

跑 `python3 tools/decode_diag.py -p /dev/wheeltec_controller`，看 `imu=` 那一栏：

| 显示 | 含义 |
|---|---|
| `正常` | 读到了 |
| `SCL拉不高` / `SDA拉不高` | 线没接好 / 上拉缺失 / 被别的东西拉住了 |
| `总线死` | 总线状态不对 |
| `无应答` | 地址不对，或者模块没供电 |
| `读出错` | 总线在，但数据不对 |

再配合 24 字节帧里的 IMU 六轴值：

- 板子**平放静止**时 `az ≈ 9.8 m/s²`（Z 轴朝上），ax/ay ≈ 0
- 晃板子时六个值都应该跟着变
- **加速度对、陀螺仪恒为 0** → 十有八九又是"一次读 12 字节"，回去看上面那条

### 如果方向不对

- **陀螺仪 Z 正方向反了**（顺时针转读出正值）：改 `main.c` 的
  `IMU_GYRO_Z_SIGN` 为 `-1`
- **加速度轴不对**：检查模块安装方向，Z 轴必须朝上

### 为什么不用 YbImu 的串口模式

模块也支持串口（`YbImuSerialLib.py`）。不用它的原因：

- 串口是**异步推送**，数据到达时刻和我们的 20ms 控制周期对不齐
- I2C 是主机主动读，可以就在控制周期里读，时间戳天然对齐
- USART1 已经给了 RK3588，USART3 又和 I2C2 抢 PB10/PB11

## 6. 引脚占用总表

### STM32（STM32F103C8，LQFP48）

| 引脚 | 功能 | 连接 |
|---|---|---|
| PA2 | **空着** | 原 ESP32 用的 USART2_TX，已弃用 |
| PA3 | **空着** | 原 ESP32 用的 USART2_RX，已弃用 |
| PA9 | USART1_TX | → CH340 RX |
| PA10 | USART1_RX | ← CH340 TX |
| PA11 | CAN1_RX | ← CAN 收发器 RXD |
| PA12 | CAN1_TX | → CAN 收发器 TXD |
| PB0 | GPIO 输出 | → 电机继电器 IN |
| PB1 | GPIO 输出 | → 水泵继电器 IN |
| PB10 | GPIO/软件 I2C SCL | → YbImu SCL |
| PB11 | GPIO/软件 I2C SDA | → YbImu SDA |
| 5V | 电源 | 供电输入 / 给继电器模块 |
| 3V3 | 电源 | 板载稳压输出 / 给 IMU |
| GND | 地 | 必须和 CH340、收发器、IMU、继电器共地 |

**内部占用（不占外部引脚）**：TIM2 做 1ms 时基、SysTick 给 `Delay_ms/us` 用。

> IMU 走的是**位翻转** I2C（`hardware/YbImu.c`），没有用硬件 I2C2 外设，
> 所以 PB10/PB11 是当普通开漏 GPIO 用的。原因见第 5 节。
>
> **其他空闲的 I2C 备选**：I2C1 在 PB6/PB7（`hardware/OLED.c` 占着做软件 I2C，未调用）；
> I2C1 重映射在 PB8/PB9（但那两个也是 CAN1 的重映射脚，留着）。

## 8. 上电检查顺序

按这个顺序最省时间：

1. **不接任何负载**（电机、水泵都摘掉），只上电
2. 听继电器——**不应该有任何吸合声或嗡嗡声**
   - 有嗡嗡声 → 先查继电器模块的 VCC/GND 是不是和 STM32 同一路电源、有没有共地
3. 停掉厂商底盘节点，跑 `python3 tools/decode_diag.py -p /dev/wheeltec_controller`
   - 没有任何输出 → 串口 TX/RX 接反了，或者没共地（先查 PA9/PA10 那两根）
   - `ok` 在涨 → 串口通了
4. 看 `坏帧` 在不在涨
   - 一直涨 → 波特率不对（应该是 115200）
5. 发一条很慢的直行命令，看 `1号/2号 目标` 有没有数值
6. 有目标值但 `实际` 一直是 0 → 看 `电流` 那两栏，按 README 的表分辨是
   "驱动器没给力"还是"被堵住"，再查使能 / 功率电 / CAN 线 / 电机 ID
7. 一切正常后再接电机负载，最后接水泵

> **轮子悬空再测。** 上一次在地面上直接发原地转向命令，车窜出去把电源撞断了。

## 9. 诊断数据（排查用）

`tools/decode_diag.py` 每帧打一行，各栏含义：

| 栏 | 含义 |
|---|---|
| `seq` | 诊断帧序号（自增）。断档就是丢帧，脚本会提示累计丢帧数 |
| `vx` / `wz` | STM32 用轮速正解出的车体速度 |
| `1号/2号 目标` | **最终发给驱动器**的转速 RPM（= 逆解目标 + 轮速外环修正）|
| `1号/2号 实际` | 驱动器回码的实际转速 RPM |
| `1号/2号 电流` | **驱动器输出扭矩电流**（单位 A，协议是 A×10），判断有没有劲的关键 |
| `外环修正` | 只有用 `--drive` 时才显示：目标减去主机理论目标 = 外环加了多少 |
| `模式` | 驱动器当前工作模式：速度 / 位置 / 电压 / 力矩 |
| `故障` | 驱动器故障码，内置了中文名（欠压/过流/堵转…）|
| `can_err` | STM32 CAN 发送失败次数 |
| `坏帧` / `ok` / `溢出` | 串口统计，正常时 `溢出` 应该是 0 |
| `relay` | bit0 电机继电器 bit1 水泵继电器 |
| `imu` | IMU 诊断码，见第 5 节 |

> ⚠️ **串口是独占的**：厂商 ROS 节点开着的时候脚本打不开同一个口。
> 看诊断数据必须先停节点，看完再起回来。
