# 从 `/cmd_vel` 到轮速：业务语义与数学方法

> 适用固件：`firmware/stm32-chassis/`（达妙 DM-H65 纯桥版本，分支 `damiao-bridge`）
> 相关文档：[`vehicle-params.md`](vehicle-params.md)（车型参数/方向系数）、[`latency-report-2026-10-28.md`](latency-report-2026-10-28.md)（响应实测）
> 代码锚点都以 `firmware/stm32-chassis/user/main.c` 为准（行号随改动会漂，按函数名搜索更稳）

## 第一部分：`/cmd_vel` 业务上是什么

### 1.1 一句话

`/cmd_vel` 是 **"此刻、车体坐标系下的目标速度"**，ROS 标准消息 `geometry_msgs/msg/Twist`。
业务上它说的是"**以什么速度前进、以什么速率转向**"，**不是**"到哪去"。

### 1.2 字段含义（我们只用得上两个）

| 字段 | 单位 | 业务含义 | 差速车 |
|---|---|---|---|
| `linear.x` | **m/s** | 车头方向前进/后退速度（+ 前进） | ✅ 用 |
| `linear.y` | m/s | 向左横移速度（+ 往左） | ❌ 无横移机构，丢弃 |
| `linear.z` | m/s | 升降 | ❌ 丢弃 |
| `angular.x` / `angular.y` | rad/s | 俯仰 / 横滚 | ❌ 丢弃 |
| `angular.z` | **rad/s** | 绕竖轴转向（**+ = 左转 = 逆时针**） | ✅ 用 |

我们的底盘对外只有 **2 个自由度**：`vx`（前进多快）+ `wz`（转多快）。
其余 4 个字段在串口协议里仍然打包，固件直接忽略（`main.c` 的 `Cmd_Apply()`，注释写明"差速车没有横向自由度"）。

### 1.3 它不是什么

- **不是位置目标**："去 (5, 3)" 是导航层的 `/goal_pose` / Nav2 的事；`/cmd_vel` 是导航算完后落到速度级的接口。
- **不是电机指令**：里面没有 RPM / 占空比 / 电流。**m/s → 轮子 rad/s 是底盘驱动的职责**。
- **不是一段轨迹**：没有时间、没有加速度，只有"这一瞬间的目标值"，没有"走 2 秒"的含义。
- **不是安全承诺**：不含避障，也不承诺坡上刹得住。避障在上层，兜底在底盘（看门狗 + 驱动器保护）。

### 1.4 时间语义（最容易误解的地方）

| 角色 | 语义 |
|---|---|
| 上层发布者 | **持续发布**的"当前期望"（Nav2、手柄遥控通常 10~20 Hz 连续发） |
| 特例 | `teleop_twist_keyboard`（humble 版）**按一次键只发一条** Twist |
| 底盘驱动 | 把最后收到的那条当作**持续有效的目标**（零阶保持） |
| 我们的 STM32 | 最后一条命令 **800 ms** 内有效，过期把目标归零并减速停车（`CMD_TIMEOUT_MS`） |

业务推论：**"一直发" = "一直授权"；"停发" = "请求停车"**。所以遥控松手就停是设计行为，不是 bug。

### 1.5 契约

```
上层（RK3576 / RK3588 / Nav2 / 遥控）        底盘（STM32 + 达妙驱动器）
  "我此刻要 0.35 m/s、0.2 rad/s"      ──►   忠实执行（换算成两轮 rad/s 下发）
  "告诉我你实际走了多少"               ◄──   忠实上报（实测轮速反解 vx/wz → /odom）
```

一句话：**上层决定"该多快"，底盘只保证"多快就是多快 + 如实汇报"**。
这是旧固件 Boost / Trim / 力矩模式全部删除后定下的原则（见 `docs/division-of-labor.md`）。

## 第二部分：数学方法

### 2.1 符号

| 符号 | 含义 | 单位 |
|---|---|---|
| `v` | 车体前进速度（= `linear.x`） | m/s |
| `ω` | 车体偏航角速度（= `angular.z`） | rad/s |
| `v_L`, `v_R` | 左/右轮接地点的线速度（沿车头方向为正） | m/s |
| `ω_L`, `ω_R` | 左/右电机的**角速度**（下发值） | rad/s |
| `r` | 轮半径 | m |
| `L` | 轮距（左右轮接地点间距） | m |
| `s_L`, `s_R` | 安装方向系数，`+1` 表示"电机正转 = 车前进" | — |

我们两台车的取值：

| 车型 | `r` | `L` | `s_L` | `s_R` | 安装方式 |
|---|---|---|---|---|---|
| sweeper（扫地车） | 0.0855 m | **0.716 m** | `+1` | `−1` | 镜像安装 |
| scrubber（洗地车） | 0.0855 m | **0.456 m** | `−1` | `−1` | 同向安装 |

> `r` 来自轮径 171 mm；`L` 由 Keil target 的 `-D TRACK_WIDTH_MM` 传（`main.c` 里有 `#ifndef ... #error` 守门）。
> `s_L/s_R` 是车身装配属性，按 `VEHICLE_SEL` 分开定义，详见 `docs/vehicle-params.md §4.1`。

### 2.2 正向：轮速 → 车体速度

两个接触点必须绕**同一个瞬时旋转中心（ICR）** 以同一个 `ω` 旋转（纯滚动无滑移假设）：

```
v_L = ω · (R_arc − L/2)
v_R = ω · (R_arc + L/2)
v   = ω ·  R_arc
```

其中 `R_arc` 是车体中心到 ICR 的距离（= 转弯半径）。相加/相减得：

```
v = (v_R + v_L) / 2
ω = (v_R − v_L) / L
```

矩阵形式（正向 Jacobian）：

```
┌ v ┐   ┌  1/2    1/2 ┐ ┌ v_L ┐
│   │ = │             │ │     │
└ ω ┘   └ −1/L    1/L  ┘ └ v_R ┘
```

### 2.3 逆向：车体速度 → 轮速（固件做的这一步）

```
v_L = v − ω · L/2
v_R = v + ω · L/2
```

```
┌ v_L ┐   ┌ 1   −L/2 ┐ ┌ v ┐
│     │ = │          │ │   │        det = L ≠ 0  → 恒可逆，无奇异点
└ v_R ┘   └ 1   +L/2 ┘ └ ω ┘
```

再换成**电机角速度**（除以轮半径、乘安装符号）：

```
ω_L = s_L · (v − ω·L/2) / r
ω_R = s_R · (v + ω·L/2) / r
```

合起来：

```
w = S · A · q / r ,   q = (v, ω)ᵀ ,   S = diag(s_L, s_R) ,   A = [[1, −L/2], [1, +L/2]]
```

> 注意区分两个空间：
> **"物理空间"**（车体/轮胎方向）和 **"命令空间"**（发给驱动器的 rad/s）。
> `s` 只负责把二者对齐，不改变数学。

### 2.4 常数与折算系数

| 换算 | 公式 | sweeper | scrubber |
|---|---|---|---|
| 前进：`v → ω_motor` | `1/r` | **11.6959** rad/s 每 m/s | 同 |
| 转向：`ω → 每轮差速` | `(L/2)/r` | **4.18713** | **2.66667** |
| 单轮线速度上限 | `r · MAX_OMEGA` | 0.0855×30 = **2.565 m/s** | 同 |
| 轮周长 | `2πr` | 0.537212 m | 同 |

> `1 m/s` 对应 **111.7 rpm**（`1/0.537212×60`）。
> **轮距越大，转同样的角速度越"花钱"**：sweeper 要两轮各差 4.19 rad/s，scrubber 只要 2.67。

### 2.5 算例（sweeper，`L/2 = 0.358`）

| 指令 | 逆解 `v_L / v_R` | 命令空间 `ω_L / ω_R` rad/s | 诊断帧 `[10..13]`（×100） | 物理动作 |
|---|---|---|---|---|
| `vx=1.0, wz=0` | 1.000 / 1.000 | **+11.696 / −11.696** | +1170 / −1170 | 直行 1 m/s，111.7 rpm |
| `vx=0, wz=+0.30` | −0.1074 / +0.1074 | **−1.256 / −1.256** | −126 / −126 | 原地**左转**，偏航率 0.30 rad/s |
| `vx=0.3, wz=+0.50` | 0.121 / 0.479 | **+1.415 / −5.602** | +142 / −560 | 边走边左转 |
| `vx=2.0, wz=1.5`（上限） | 1.463 / 2.537 | **+17.11 / −29.67** | +1711 / −2967 | 右轮 29.67 < 30，刚好不撞限幅 |

**第 2 行是最反直觉的一行**：命令空间里两轮**同号**（都 −126），但物理上反向转 ——
因为右轮镜像安装（`s_R = −1`）。这就是为什么两台车的方向系数必须分开定义。

### 2.6 可行域：轮速上限映射成菱形

真实约束在轮子上：`|ω_motor| ≤ MAX_OMEGA`，等价轮子线速度 `|v_wheel| ≤ r·MAX_OMEGA = 2.565 m/s`。
代入逆向式得 `(v, ω)` 平面上的**速度多边形**（菱形）：

```
|v| + |ω| · L/2  ≤  r · MAX_OMEGA = 2.565 m/s
```

顶点：

| 车型 | `(±2.565, 0)` | `(0, ±ω_max)` |
|---|---|---|
| sweeper | 直行 ±2.565 m/s | 原地转 `±2.565/0.358 = ±7.16 rad/s` |
| scrubber | 同 | `±2.565/0.228 = ±11.25 rad/s` |

上层硬夹是矩形 `|vx| ≤ 2.0`、`|wz| ≤ 1.5`。检查最坏角点：

| 车型 | `v + ω·L/2` | 判定 |
|---|---|---|
| sweeper | 2.0 + 1.5×0.358 = **2.537** | ≤ 2.565 ✓（余量 1.1%） |
| scrubber | 2.0 + 1.5×0.228 = **2.342** | ≤ 2.565 ✓（余量 8.7%） |

**这就是 2.0 / 1.5 这组数的来历：保证矩形里任何一点都不会被轮速限幅截断。**

### 2.7 被限幅截断之后会怎样（一个容易被忽略的非线性）

限幅是**按轮各夹各的**，所以超限时不是"整体变慢"，而是**菱形切割**。
假设只有 `v_R` 被夹：

```
v_actual = (v_L + v_R_clip) / 2      ← 变慢
ω_actual = (v_R_clip − v_L) / L      ← 转向也被改变
```

数学上等于把期望点投影到约束边界，于是**直行速度和偏航率会同时丢，转弯半径还会变**。
表现是"车能走但走歪"，而诊断帧里 `[2..3]` 的 vx 还是原始值（没夹），只有 `[10..13]` 目标 ω 能看出被夹。

### 2.8 标定：轮径误差和轮距误差作用在不同地方

设真实值 `r'`、`L'`，代码里用的是 `r`、`L`，代入正向式子：

```
v_actual = (r'/r) · v_cmd                 ← 只由轮径决定
ω_actual = (r'/r) · (L/L') · ω_cmd        ← 轮径 + 轮距共同决定
```

**两步标定法**：

1. 直行：命令 `vx = 0.2 m/s` 走 2 m，量实际位移 `d` → `k_v = d / 2 = r'/r`
2. 原地转：转 360°，量实际转角（陀螺或记号）→ `k_ω = ω_actual / ω_cmd`
3. 反解轮距：`L' = L · k_v / k_ω`

> 这也解释了"**轮距错的话直行看不出来**"：`v_actual` 里没有 `L`。
>
> ⚠️ 更危险的坑：`/odom` 用的是同一组 `r`、`L` 做反向，参数错了**上报也是错的、而且反向错**，
> 于是"命令→实际"和"实际→上报"两处误差会互相抵消一部分 —— 闭环看着很正常，开环一走就偏。

### 2.9 离散化与带宽

- STM32 每 **20 ms** 做一次逆解下发（`CTRL_PERIOD_MS`，零阶保持）；这 20 ms 内目标恒定，驱动器按自己的速度环去追。
- 数学上"瞬时逆解"是对的；物理上是**阶梯输入 → 二阶欠阻尼响应**：
  实测 0.2 m/s 阶跃，上升时间 ~250 ms、过冲 +26%、稳态 −9%（见 `latency-report-2026-10-28.md`）。
  做轨迹跟踪时必须把这个环节当被控对象建模。
- 串口数值分辨率：`vx` 为 mm/s、`wz` 为 mrad/s → 轮速分辨率 `0.0117` / `0.0042 rad/s`，可忽略。

### 2.10 轨迹（积分）——上层做里程计时用

给定恒定的 `(v, ω)`：

```
θ(t) = θ₀ + ω·t
ω ≠ 0： x(t) = x₀ + (v/ω)·(sin θ(t) − sin θ₀)
        y(t) = y₀ − (v/ω)·(cos θ(t) − cos θ₀)
ω = 0： x(t) = x₀ + v·cos θ₀·t
        y(t) = y₀ + v·sin θ₀·t
```

转弯半径 `R_arc = v/ω`。STM32 **不做里程计**，只上报 `vx`/`wz`（实测值），积分在上位机（厂商节点 + EKF）。

## 第三部分：固件实现对照

### 3.1 数据流

```
/cmd_vel (Twist)          厂商节点打包 11B           STM32 逆解+换算           CAN 帧
 vx [m/s]   ───────────►  tx[3..4] = vx*1000  ──►   v_L / v_R      ──►  0x200+ID
 wz [rad/s]               tx[7..8] = wz*1000        ↓ ω = s·v/r           float32 小端
                          (vy 也打包, 固件丢弃)       夹 ±30 rad/s          (DLC=4)
```

| 步骤 | 代码位置 | 说明 |
|---|---|---|
| 收帧/校验 | `Cmd_FeedByte()` / `Cmd_Verify()` | 帧头 `0x7B`、帧尾 `0x7D`、BCC 全对才接受；**非法帧丢弃且不刷新看门狗** |
| 解析 | `Cmd_Apply()`（`g_cmd_vx_mm = f[3]<<8\|f[4]`） | `vx` mm/s、`wz` mrad/s，大端 int16 |
| 有效期 | `Bridge_Update()`（`CMD_TIMEOUT_MS = 800`） | 过期 → `g_eff_* = 0`（**只清零，不失能**：失能=输出关断=不制动会溜车） |
| 逆解 | `Control_Tick()`：`v_left = vx − wz·TRACK/2`、`v_right = vx + wz·TRACK/2` | 2.3 节公式 |
| 换算+夹取 | `g_target_omega[i] = DM_DIR_x * ClampF(v/R, ±MAX_OMEGA_RAD_S)` | `MAX_OMEGA_RAD_S = 30` |
| 下发 | `DM_SendSpeed()` → 标准帧 `0x200+CAN_ID` | float32 小端 rad/s |
| 反解上报 | `Send_MainTelemetry()`：`v_left = DM_DIR_LEFT·ω_fb·R` … `vx=(v_L+v_R)/2`、`wz=(v_R−v_L)/L` | **用实测反馈，不是目标值** |

### 3.2 关键宏

| 宏 | 值 | 位置 |
|---|---|---|
| `WHEEL_R_M` | `0.0855f` | `main.c` 顶部几何常量区 |
| `TRACK_WIDTH_MM` / `TRACK_WIDTH_M` | 716 / 456 → `/1000` | 由 Keil target Define 传入，有 `#error` 守门 |
| `MAX_OMEGA_RAD_S` | `30.0f`（≈2.565 m/s） | 同上 |
| `DM_DIR_LEFT` / `DM_DIR_RIGHT` | sweeper `+1/−1`；scrubber `−1/−1` | 按 `VEHICLE_SEL` 分支定义 |
| `CMD_TIMEOUT_MS` | `800` | 命令看门狗 |
| `FB_TIMEOUT_MS` | `2000` | 反馈超时 → 该轮目标强制 0 + offline |
| `CTRL_PERIOD_MS` / `STATUS_PERIOD_MS` | `20` / `50` | 控制 50 Hz / 上报 20 Hz |

### 3.3 关于驱动器侧（建议一起看 `docs/` 里的下一步计划）

固件**只写 `CTRL_MODE(0x0A)=3`（速度模式）**，不读写其它寄存器。因此下面这些量目前都是**出厂默认值**：

| 寄存器 | 含义 | 对这段数学的影响 |
|---|---|---|
| `0x06 MAX_SPD` | 速度模式限速（rad/s） | 若小于我们下发的值，会被**静默夹小**，表现为"速度忠实度总是差一点" |
| `0x04/0x05 ACC/DEC` | 加/减速（**Krad/s²**） | 决定阶跃响应形状（实测 +26% 过冲） |
| `0x09 TIMEOUT` | CAN 通讯超时（50 µs 计数，仅使能时生效） | **STM32 挂掉时的最后一层保护**；超时动作是退使能（不制动） |
| `0x19/0x1A KP_ASR/KI_ASR`、`0x20 V_BW` | 速度环参数 | 决定跟踪误差与带宽 |

> 计划：启动时用 `0x33` 参数读把上面这些读回来放进诊断帧/启动日志，就能把"出厂默认"变成实测值。

## 第四部分：常见误解速查

| 误解 | 事实 |
|---|---|
| "`cmd_vel` 是位置指令" | 是**速度**指令；位置是导航层的事 |
| "发一次就够，底盘会一直跑" | 上层要持续发；固件 800 ms 收不到就归零减速停车 |
| "`linear.y` 可以用来横移" | 差速车无横移自由度，固件直接丢弃 |
| "`wz>0` 是右转" | ROS 约定 **正 = 逆时针 = 左转** |
| "轮速就是 RPM 直接发" | 发的是 **rad/s**，且要先做差速逆解 + 乘安装方向系数 |
| "轮距填错只影响转弯" | 影响转向增益 **和** `/odom` 上报的 wz，且两者反向抵消（最危险） |
| "固件有加减速限制" | 没有；斜坡在驱动器内部（`ACC/DEC`，未配置） |
| "限幅是整体按比例缩小" | 是按轮各夹各的，会造成速度+转向同时偏移 |
